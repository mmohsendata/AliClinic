# Absher — إدارة المختبر

تطبيق محلي عربي باتجاه RTL لإدارة ملفات المرضى، كتالوج التحاليل، طلبات المختبر، تتبع العينات، إدخال النتائج، واعتماد النتائج. التخزين حالياً في ملف JSON واحد خارج مجلد الملفات الثابتة، ويُستبدل ذرياً مع قفل للكتابة.

> **نطاق هذه النسخة:** هذا أساس تشغيلي لمسار المختبر الأساسي، وليس تنفيذًا كاملاً لكل وحدات المواصفات المرفقة. يتضمن إنشاء المستخدمين وتعيين أدوار ثابتة من واجهة المدير، لكنه لا يتضمن صلاحيات مخصصة أو إدارة وصول حسب الفرع. لا يتضمن حالياً الفوترة والتحصيل، المخزون، الموظفين والحضور، إدارة الفروع، استيراد/تصدير البيانات، النسخ الاحتياطي والاستعادة من الواجهة، أو إنشاء PDF. صفحة التقرير المعتمدة قابلة للطباعة من المتصفح. لا توجد نطاقات مرجعية طبية افتراضية؛ يجب مراجعة أي قيم سريرية واعتمادها بواسطة مختصين مؤهلين قبل الاستخدام السريري.

## المتطلبات

- Python 3.12 أو أحدث
- Windows PowerShell

## التثبيت والتشغيل على Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:SECRET_KEY = (python -c "import secrets; print(secrets.token_hex(32))").Trim()
flask --app run.py main create-admin
flask --app run.py run
```

أنشئ اسم مستخدم المدير عند طلبه، ثم أدخل كلمة مرور أولية من 12 حرفاً على الأقل. بعد تسجيل الدخول، تظهر صفحة تغيير كلمة المرور قبل فتح بقية الصفحات. افتح `http://127.0.0.1:5000`. احتفظ بقيمة `SECRET_KEY` للجلسات المحلية؛ استخدم قيمة عشوائية دائمة في إعداد بيئة التشغيل، ولا تضعها في المستودع.

في Windows PowerShell، للاحتفاظ بسر جلسات ثابت بعد إغلاق الطرفية أو إعادة التشغيل، أنشئه مرة واحدة داخل مجلد البيانات المحلي ثم حمّله قبل كل تشغيل:

```powershell
New-Item -ItemType Directory -Force data | Out-Null
python -c "import secrets; print(secrets.token_hex(32))" | Set-Content -NoNewline data\secret_key.txt
$env:SECRET_KEY = (Get-Content -Raw data\secret_key.txt).Trim()
```

لا تشارك ملف المفتاح أو ترفعه؛ مجلد `data` مستثنى من Git.

## النشر على Render

المستودع يتضمن `render.yaml` لإعداد خدمة Render Blueprint. اربط مستودع GitHub واختر **New + → Blueprint**, ثم اسمح لـ Render بإنشاء الإعدادات من الملف. خدمة الويب تستخدم Gunicorn (`run:app`)، وفحص صحة على `/health`، وسر جلسة يولّده Render، وقرصاً دائماً مثبتاً في `/var/data` لحفظ `store.json` بين عمليات النشر وإعادة التشغيل. إعداد `COOKIE_SECURE=true` يفعّل كوكيز HTTPS الآمنة. ينشئ مخزن JSON قفلاً جديداً لكل عملية، وهو متوافق مع نموذج Gunicorn الذي ينشئ العمال باستخدام fork.

تتطلب إعدادات Blueprint هذه خطة Render مدفوعة تدعم الأقراص الدائمة. إذا أنشأت الخدمة يدوياً، اضبط `DATA_FILE=/var/data/store.json` وأضف قرصاً دائماً مثبتاً على `/var/data`، وكذلك `SECRET_KEY` و`COOKIE_SECURE=true`. لا يكفي تعريف `DATA_FILE` دون إرفاق القرص، ولا يكفي القرص إذا كان التطبيق لا يستخدم مساره. لا تغيّر الخدمة إلى خطة مجانية أو تحذف القرص إذا كانت البيانات المسجلة مهمة؛ نظام الملفات للخدمات المجانية مؤقت وقد تُفقد بيانات JSON عند إعادة النشر أو إعادة التشغيل. احتفظ بنسخ احتياطية مشفرة مستقلة. بعد أول نشر، أنشئ المدير من Render Shell بالأمر `flask --app run.py main create-admin`، ثم سجّل الدخول وغيّر كلمة المرور. لا تشغّل `seed-demo` على بيانات المرضى الفعلية.

لتعبئة الصفحات بسجلات وهمية واضحة قبل الاستخدام، نفّذ `flask --app run.py main seed-demo` بعد إنشاء المدير وقبل تشغيل الموقع. الأمر يرفض إضافة المزيد إذا كانت هناك سجلات مرضى أو تحاليل أو طلبات موجودة. كل السجلات التجريبية تحمل علامة، والنتائج النصية تحذّر من أنها غير صالحة للتشخيص. لا تستخدمها كبيانات طبية.

لتثبيت Flask CLI في جلسة PowerShell جديدة، عيّن `SECRET_KEY` مجدداً قبل أوامر `flask`. يمكن نسخ `.env.example` كمرجع لإعدادات البيئة؛ التطبيق لا يحمّل ملفات `.env` تلقائياً.

يُحفظ ملف البيانات الافتراضي في `data\store.json`. لتغيير المسار، عيّن متغير البيئة `DATA_FILE` إلى مسار مطلق قبل التشغيل. لا تضع الملف في `app\static` أو أي مجلد يُقدّم للويب.

## مسار الاستخدام

1. سجّل الدخول كمدير وغيّر كلمة المرور الأولية.
2. أضف التحاليل وأسعارها من كتالوج التحاليل.
3. سجّل المريض، ثم أنشئ طلباً وحدد تحليلاً واحداً أو أكثر.
4. من الطلب حدّث العينة إلى «مستلمة» أو «تم السحب».
5. يسجل فني المختبر النتيجة؛ ثم يعتمدها مستخدم بدور المراجع.
6. بعد الاعتماد يظهر التقرير القابل للطباعة. التقرير يوضح صراحةً أن الوحدات والنطاقات المرجعية غير معتمدة في هذا الإصدار.

الأدوار المدعومة في الواجهة: `admin`، `receptionist`، `technician`، `reviewer`. أنشئ المدير الأول عبر أمر CLI؛ يمكن للمدير بعد ذلك إنشاء حسابات بهذه الأدوار من صفحة المستخدمين. يفرض الخادم قيود الأدوار على مسارات المرضى والطلبات وإدخال النتائج والمراجعة.

## ملاحظات تشغيل وأمان

- CSRF مفعّل لنماذج التغيير، وكلمات المرور مخزنة باستخدام Werkzeug password hashing، والجلسات تستخدم HttpOnly وSameSite=Lax.
- يُفرض التفويض على الخادم لمسارات المختبر، وليس بإخفاء عناصر الواجهة فقط. يتطلب النشر HTTPS وضبط `COOKIE_SECURE=true` ومراجعة حدود الوصول والتسجيل والنسخ الاحتياطي.
- عمليات الكتابة على الملف محمية بقفل وكتابة ذرية. احتفظ بنسخ احتياطية مشفرة خارج مجلد التطبيق قبل أي استخدام تشغيلي؛ لا توجد واجهة نسخ احتياطي/استعادة مدمجة بعد.
- هذا التطبيق لا يدّعي الامتثال لأي قانون خصوصية صحي، ولا يغني عن مراجعة أمنية وقانونية أو تحقق سريري.
