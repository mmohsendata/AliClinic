# Absher — إدارة المختبر

تطبيق محلي عربي باتجاه RTL لإدارة ملفات المرضى، كتالوج التحاليل، طلبات المختبر، تتبع العينات، إدخال النتائج، واعتماد النتائج. التخزين حالياً في ملف JSON واحد خارج مجلد الملفات الثابتة، ويُستبدل ذرياً مع قفل للكتابة.

> **نطاق هذه النسخة:** هذا أساس تشغيلي لمسار المختبر الأساسي، وليس تنفيذًا كاملاً لكل وحدات المواصفات المرفقة. يتضمن إنشاء المستخدمين وتعيين أدوار ثابتة من واجهة المدير، لكنه لا يتضمن صلاحيات مخصصة أو إدارة وصول حسب الفرع. تتضمن صفحة المخزون تسجيل المشتريات، تحديد كمية استهلاك لكل تحليل، وخصمها تلقائياً مرة واحدة عند إدخال النتيجة لأول مرة؛ تُسجل الكميات المستهلكة حتى عند عدم كفاية الرصيد، ويظهر المخزون السالب أو عند حد إعادة الطلب كتنبيه. كما تتضمن تتبع الحضور للمستخدمين الذين يفعّلهم المدير، بجدول أسبوعي مؤرخ وأجر بالساعة، وإيقاف احتساب الوقت عند الخمول، وخصومات التأخير، ومراجعة الأعذار، وملخص راتب شهري تقديري. يعتمد احتساب الأجر على جلسات النظام النشطة وسياسة الخمول والإعدادات المحددة، وليس سجلاً معتمداً للرواتب أو الحضور القانوني؛ راجع القوانين وسياسات العمل المحلية قبل استخدامه لاتخاذ قرارات الرواتب. لا يتضمن حالياً الفوترة والتحصيل، إدارة الفروع، استيراد/تصدير البيانات، تسويات المخزون، النسخ الاحتياطي والاستعادة من الواجهة، أو إنشاء PDF. يمكن طباعة التقرير المعتمد من المتصفح. تتوفر قوالب نتائج أولية بمصادر إنترنت موثقة، لكن النطاقات المنشورة أمثلة عامة وليست معياراً مصرياً؛ تبقى غير معتمدة حتى يراجعها المختبر ويضبط الوحدات والنطاقات لطريقة القياس والسكان المحليين.

## المتطلبات

- Python 3.12 أو أحدث
- Windows PowerShell

## التثبيت والتشغيل على Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:SECRET_KEY = (python -c "import secrets; print(secrets.token_hex(32))").Trim()
flask --app run.py main create-admin
flask --app run.py run
```

أنشئ اسم مستخدم المدير عند طلبه، ثم أدخل كلمة مرور أولية من 12 حرفاً على الأقل. بعد تسجيل الدخول، تظهر صفحة تغيير كلمة المرور قبل فتح بقية الصفحات. افتح `http://127.0.0.1:5000`. احتفظ بقيمة `SECRET_KEY` للجلسات المحلية؛ استخدم قيمة عشوائية دائمة في إعداد بيئة التشغيل، ولا تضعها في المستودع.

في Windows PowerShell، للاحتفاظ بسر جلسات ثابت بعد إغلاق الطرفية أو إعادة التشغيل، أنشئه مرة واحدة داخل مجلد البيانات المحلي ثم حمّله قبل كل تشغيل:

```powershell
New-Item -ItemType Directory -Force data | Out-Null
python -c "import secrets; print(secrets.token_hex(32))" | Set-Content -NoNewline data\secret_key.txt
$env:SECRET_KEY = (Get-Content -Raw data\secret_key.txt).Trim()
```

لا تشارك ملف المفتاح أو ترفعه؛ مجلد `data` مستثنى من Git.

## النشر على Render

المستودع يتضمن `render.yaml` لإعداد خدمة Render Blueprint. اربط مستودع GitHub واختر **New + → Blueprint**, ثم اسمح لـ Render بإنشاء الإعدادات من الملف. خدمة الويب تستخدم Gunicorn (`run:app`)، وفحص صحة على `/health`، وسر جلسة يولّده Render، وقرصاً دائماً مثبتاً في `/var/data` لحفظ `store.json` بين عمليات النشر وإعادة التشغيل. إعداد `COOKIE_SECURE=true` يفعّل كوكيز HTTPS الآمنة. ينشئ مخزن JSON قفلاً جديداً لكل عملية، وهو متوافق مع نموذج Gunicorn الذي ينشئ العمال باستخدام fork.

تتطلب إعدادات Blueprint هذه خطة Render مدفوعة تدعم الأقراص الدائمة. إذا أنشأت الخدمة يدوياً، اضبط `DATA_FILE=/var/data/store.json` وأضف قرصاً دائماً مثبتاً على `/var/data`، وكذلك `SECRET_KEY` و`COOKIE_SECURE=true`. لا يكفي تعريف `DATA_FILE` دون إرفاق القرص، ولا يكفي القرص إذا كان التطبيق لا يستخدم مساره. لا تغيّر الخدمة إلى خطة مجانية أو تحذف القرص إذا كانت البيانات المسجلة مهمة؛ نظام الملفات للخدمات المجانية مؤقت وقد تُفقد بيانات JSON عند إعادة النشر أو إعادة التشغيل. احتفظ بنسخ احتياطية مشفرة مستقلة.

لإنشاء مدير اختبار على Render، أضف `BOOTSTRAP_ADMIN_USERNAME=admin` و`BOOTSTRAP_ADMIN_PASSWORD` كمتغيرات بيئة خاصة بالخدمة. استخدم كلمة مرور مؤقتة فريدة وعشوائية لا تقل عن 16 حرفاً؛ لا تستخدم `admin` ككلمة المرور. عند بدء التطبيق، ينشئ الحساب فقط إذا لم يوجد مدير نشط، ويخزن كلمة المرور كـ hash ويطلب تغييرها عند أول دخول. احتفظ بمتغير كلمة المرور كخيار استعادة إذا كنت تستخدم تخزين Render المجاني المؤقت؛ عند فقد ملف JSON بعد إعادة نشر، سيعيد التطبيق إنشاء المدير بهذا السر الخاص. احذف المتغير فقط عند توفر تخزين دائم، وبعد التأكد من وجود مدير نشط. لا تسجل كلمة المرور في Git أو السجلات.

لتعبئة الصفحات بسجلات وهمية واضحة قبل الاستخدام، نفّذ `flask --app run.py main seed-demo` بعد إنشاء المدير وقبل تشغيل الموقع. الأمر يرفض إضافة المزيد إذا كانت هناك سجلات مرضى أو تحاليل أو طلبات موجودة. كل السجلات التجريبية تحمل علامة، والنتائج النصية تحذّر من أنها غير صالحة للتشخيص. لا تستخدمها كبيانات طبية.

لتثبيت Flask CLI في جلسة PowerShell جديدة، عيّن `SECRET_KEY` مجدداً قبل أوامر `flask`. يمكن نسخ `.env.example` كمرجع لإعدادات البيئة؛ التطبيق لا يحمّل ملفات `.env` تلقائياً.

يُحفظ ملف البيانات الافتراضي في `data\store.json`. لتغيير المسار، عيّن متغير البيئة `DATA_FILE` إلى مسار مطلق قبل التشغيل. لا تضع الملف في `app\static` أو أي مجلد يُقدّم للويب.

## مسار الاستخدام

1. سجّل الدخول كمدير وغيّر كلمة المرور الأولية.
2. من كتالوج التحاليل يمكن للمدير استيراد القوالب الشائعة، ثم مراجعة حقول النتائج والوحدات والنطاقات والمصادر وتأكيد التحقق المحلي. يمكنه أيضاً إعداد قالب لنتيجة تحليل جديد. القوالب المستوردة تبدأ كمسودات، ولا يمكن طلب هذه التحاليل حتى يعتمد المختبر نطاقاتها محلياً.
3. من صفحة المخزون أضف المستلزمات ووحدات قياسها، وسجّل المشتريات، ثم عيّن كمية الاستهلاك لكل تحليل. يحتفظ كل طلب بوصفة الاستهلاك التي كانت محددة وقت إنشائه.
4. سجّل المريض، ثم أنشئ طلباً وحدد تحليلاً واحداً أو أكثر.
5. من الطلب حدّث العينة إلى «مستلمة» أو «تم السحب».
6. يسجل فني المختبر قيماً لكل حقل في قالب التحليل أو نتيجة نصية للتحليل غير المهيأ؛ عند أول حفظ تُسجل كميات وصفة التحليل كمستهلكة مرة واحدة، ثم يعتمدها مستخدم بدور المراجع.
7. بعد الاعتماد يظهر التقرير القابل للطباعة مع قيم النتائج والوحدات والنطاقات ومصادر القوالب وحالة التحقق المحلي.

تستند أمثلة القوالب إلى مصادر مثل [UCSF Health: CBC](https://www.ucsfhealth.org/care/medical-tests/cbc-blood-test)، و[UCSF Health: CMP](https://www.ucsfhealth.org/care/medical-tests/comprehensive-metabolic-panel)، و[UCSF Health: Urinalysis](https://www.ucsfhealth.org/care/medical-tests/urinalysis)، و[CDC: Diabetes Testing](https://www.cdc.gov/diabetes/diabetes-testing/)، و[MedlinePlus: Cholesterol Levels](https://medlineplus.gov/lab-tests/cholesterol-levels/). توضح [MedlinePlus: Understanding Lab Results](https://medlineplus.gov/lab-tests/how-to-understand-your-lab-results/) أن النطاقات تختلف حسب المختبر والطريقة والفئة السكانية؛ لذلك لا تُعد هذه الأمثلة بديلاً عن النطاقات التي يتحقق منها المختبر المحلي.

الأدوار المدعومة في الواجهة: `admin`، `receptionist`، `technician`، `reviewer`. تعرض صفحة المخزون الأرصدة وسجل الحركات للمدير وفني المختبر؛ إدارة الأصناف والمشتريات ووصفات الاستهلاك متاحة للمدير فقط. أنشئ المدير الأول عبر أمر CLI؛ يمكن للمدير بعد ذلك إنشاء حسابات بهذه الأدوار من صفحة المستخدمين. يفرض الخادم قيود الأدوار على مسارات المرضى والطلبات وإدخال النتائج والمراجعة.

من صفحة **الحضور والرواتب** يختار المدير المستخدمين الذين تُتبع جلساتهم، ويحدد أجر الساعة والورديات الأسبوعية وأيام العمل والعطلات وفترة سريان الجدول. يقيس التطبيق النشاط بتفاعلات الصفحة ويرسل نبضات أثناء الاستخدام؛ عند انتهاء مهلة الخمول يغلق الجلسة عند آخر نشاط مضافاً إليه المهلة، وتستأنف جلسة جديدة عند عودة الاستخدام. تسجيل الخروج يغلق الجلسة. يُحسب الأجر الإجمالي من وقت الجلسات النشطة × سعر الساعة، ثم يُخصم التأخير الزائد عن فترة السماح بنفس سعر الساعة. يمكن للموظف تقديم عذر، واعتماده يلغي خصم التأخير لذلك التاريخ دون إضافة ساعات غير مسجلة. ساعات الجدول هي معلومات تخطيطية؛ لا تُضاف تلقائياً إلى ساعات الأجر.

تُفسر أوقات الورديات وتواريخ الرواتب وفق المنطقة الزمنية المحلية لخادم التشغيل؛ اضبطها على منطقة عمل المختبر قبل الاستخدام. يُخزن وقت الجلسة مع إزاحة المنطقة الزمنية، وتُوزع الجلسات التي تعبر حد الشهر على الفترتين.

## ملاحظات تشغيل وأمان

- CSRF مفعّل لنماذج التغيير، وكلمات المرور مخزنة باستخدام Werkzeug password hashing، والجلسات تستخدم HttpOnly وSameSite=Lax.
- يُفرض التفويض على الخادم لمسارات المختبر، وليس بإخفاء عناصر الواجهة فقط. يتطلب النشر HTTPS وضبط `COOKIE_SECURE=true` ومراجعة حدود الوصول والتسجيل والنسخ الاحتياطي.
- عمليات الكتابة على الملف محمية بقفل وكتابة ذرية. احتفظ بنسخ احتياطية مشفرة خارج مجلد التطبيق قبل أي استخدام تشغيلي؛ لا توجد واجهة نسخ احتياطي/استعادة مدمجة بعد.
- هذا التطبيق لا يدّعي الامتثال لأي قانون خصوصية صحي، ولا يغني عن مراجعة أمنية وقانونية أو تحقق سريري.
